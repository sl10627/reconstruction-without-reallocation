# Replication package — *Reconstruction Without Reallocation*

This package reproduces every table and figure in "Reconstruction Without
Reallocation: How Did Chilean Manufacturing Capital Adjust After the 2010 Maule
Earthquake Shock?" I treat the Maule earthquake as an exogenous shock to Chile's
manufacturing sector and estimate its effect with a difference-in-differences
design across industries and regions, using ENIA establishment data and USGS
ShakeMap intensity.

All of the tables and figures in the paper are produced by the replication
scripts, which go from the raw annual databases through extraction,
harmonization, cell construction, intensity merging, estimation, and table and
figure generation. I wrote the full pipeline in Python, and one command runs it
end to end (`code/run_all.py`). For reviewers who work in Stata or R, I also
provide a focused replication of the headline regressions in `code/stata/` and
`code/r/`, which checks itself against the Python estimates.

---

## 1. Software

- **Python** 3.11+ with the packages in `requirements.txt` (pinned to the
  versions that produced the paper; I used Python 3.13.9). Nothing in the paper
  is entered by hand. Every number comes from these scripts.
- **R** 4.x with `fixest`, for `code/r/main_did.R` (I used R 4.6.0 and fixest
  0.14.2). I read the data with base `read.csv`, so `arrow` is not needed.
  `fwildclusterboot` is not available for R ≥ 4.6, so I hand-roll the wild
  cluster bootstrap in the script instead.
- **Stata** 15+ with `reghdfe`, `ftools`, and `boottest`
  (`ssc install reghdfe ftools boottest`), for `code/stata/main_did.do`.

## 2. Data

This paper is based on data from the Annual National Industrial Survey
(*Encuesta Nacional Industrial Anual*, ENIA) collected by the Chilean National
Institute of Statistics (INE), the CASEN household survey, USGS ShakeMap
intensity polygons, and GADM administrative boundaries. None of these is
redistributed here. The scripts expect the following inputs, and everything else is
generated by the code.

| Input | Where the scripts expect it | Source |
|---|---|---|
| ENIA annual databases, 2000–2018 | `*-base-enia.accdb` at the repository root | INE |
| CASEN 2006, 2009, 2011, 2013, 2015, 2017 | `data/casen_<year>.dta` | Ministerio de Desarrollo Social |
| CASEN 2003 | `data/_casen_extract/casen2003.dta` (extracted from `casen2003stata.rar`) | Ministerio de Desarrollo Social |
| USGS ShakeMap, 2010 Maule earthquake | `geodata/shakemap_shape/` (`mi.shp` and companions) | USGS |
| GADM 4.1 Chile regions | `geodata/gadm_chile/` (`gadm41_CHL_1.shp` and companions) | GADM |
| ISIC Rev. 3.1 → Rev. 4 concordance | `crosswalks/ISIC31_ISIC4.txt` (included) | UN Statistics Division |

The publicly available FUSION files from 2008 onward use annual identifiers that
are not consistent across years, so I do not construct an
establishment-level panel for the period after 2007. Instead, all regressions
use repeated cross-sections composed of "2-digit industry × region × year"
cells. The working sample covers 2003–2017, excluding 2012 because the
establishment response rate to the questionnaire was markedly lower than in
other years.

## 3. Reproducing the paper

```
pip install -r requirements.txt
python code/run_all.py
```

`run_all.py` runs every step in dependency order, from the raw `.accdb` files to
the LaTeX tables, and finishes with `verify_numbers.py` (Section 4). A full run
takes about 12 minutes, most of it in the HonestDiD step. Each step's console output is saved to
`output/logs/<script>.log`, so every number the scripts print is on file. To
resume after a change, `python code/run_all.py --from 15` reruns step 15 and
everything after it.

| Step | Produces |
|---|---|
| `01_extract_accdb.py` | `raw/<year>_PARTE<k>.csv` from the `.accdb` files |
| `04_harmonize.py` | `data/wide_<year>.parquet` |
| `05_build_crosswalk_weights.py` | `crosswalks/rev31_to_rev4_share_weights.csv` |
| `06_build_pooled.py` | `data/enia_pooled.parquet` |
| `13_earthquake_intensity.py` | `data/shakemap_by_region.csv` (region MMI) |
| `31_remake_fig1.py` | Figure 1 |
| `15_earthquake_did.py` | cell panel, main DiD, event studies, Figure 2 |
| `16_robustness.py` | robustness of the 2014 pulse |
| `18_labor_outcomes.py` | labor outcomes |
| `19_asset_decomposition.py` | asset decomposition, Figure 3 |
| `20_net_investment.py` | net investment test |
| `21_wage_decomposition.py` | wage decomposition, Figure 4 |
| `33_wage_mechanism_checks.py` | wage-mechanism checks table |
| `22_wild_bootstrap.py` | wild cluster bootstrap (fixed seed) |

The script numbers are identifiers, not the run order: the order in
`run_all.py` follows the data dependencies (for example, 32 builds the CASEN
panel that 25, 27 and 28 read). The tables in `paper/tables/` are written
directly from the output CSVs, so the tables in the paper cannot drift from the
code.

The other scripts (02, 03, 07–12, 14, 23) are diagnostics and earlier project
directions. Nothing in the paper depends on them; `python code/run_all.py
--exploratory` runs them too.

## 4. Checking that the paper matches the code

```
python code/verify_numbers.py
```

This checks every number quoted in the paper text, and the claims stated as
bounds (such as "p < 0.01"), against the fresh `output/*.csv`. It exits 0 when
every number matches, and otherwise prints the claim that is out of sync together
with its paper-vs-pipeline values. `run_all.py` runs it as its last step.

## 5. Stata and R replication of the main results

Both scripts read one exported panel (`data/analysis_cell.csv`, written by
`34_export_analysis_cell.py` from `data/enia_cell_2digit_quake.parquet`; I also
provide a `.dta` copy) and reproduce the estimates the paper leans on: the main
DiD for investment without and with region linear trends, the raw event-study
2014 coefficient, and the headline 2014 and 2015 coefficients after
pre-period-projected detrending, with the wild cluster bootstrap of the 2014
pulse.

```
Rscript code/r/main_did.R          # fixest::feols, plus a hand-rolled wild bootstrap
stata -b do code/stata/main_did.do # reghdfe + boottest, run from the repository root
```

Run them after `run_all.py`. Each script compares its estimates with the Python
values in `data/python_benchmarks.csv` and stops with an error if a point
estimate differs by 1e-4 or more. R matches Python to machine precision,
including the bootstrap *t*-statistic (3.40), and Stata matches to about 1e-7, the
precision of the CSV export.

For the headline specification, I estimate each region's linear trend using only
the pre-earthquake years (2003 through 2009) and project it forward, then run the
event study on the deviations from this pre-period-projected path. I do not
estimate the trend on the whole sample, because that would let the
post-earthquake reconstruction pulse affect the counterfactual slope and pull the
treatment effect toward zero. Both scripts follow this same procedure.

Because there are only fifteen region clusters, I read the cluster-robust
asymptotic standard errors cautiously, and for the headline pulse I also report a
restricted wild cluster bootstrap *p*-value with Rademacher weights. This
bootstrap *p*-value moves a little with the random draws (Python 0.027, R 0.034,
Stata 0.033), so the scripts only require it to be within 0.02 of Python's.
